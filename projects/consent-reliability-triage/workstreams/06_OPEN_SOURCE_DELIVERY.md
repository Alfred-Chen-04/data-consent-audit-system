# 工作包 06：开源展示与交接

> 对应周次：10｜计划工时：4 小时

## 这一块要回答什么

怎样让维护者、研究者和面试官快速看懂问题、证据、建议和限制，并能重新生成主要结果？

## 依赖输入

- 最终分析表、排名评价、decision memo 和 METHOD
- 所有可公开证据与许可证记录
- 已冻结的结论边界

## 具体任务

1. 建立最小静态页面，展示 priority queue、finding detail、evaluation、method and limitations 以及下载链接。
2. 页面标明数据版本、最后核查日期、适用环境和建议／已执行／已评估状态。
3. 从同一份分析输出生成网页和下载文件，避免手工复制产生不一致。
4. 从干净环境按 README 重建主要分析表和候选队列，记录复现结果。
5. 检查公开材料中的许可证、来源链接、会话标识和敏感内容。
6. 更新项目 README，写一段简历 bullet 和一份 2–3 分钟面试叙事；数字只使用最终真实结果。
7. 更新 `WORKSTREAMS.md` 状态表和 `DECISION_LOG.md`，列出下一阶段 backlog。

## 产出

- 最小静态开源页面
- 完整 README 和复现命令
- 版本化分析数据、方法、memo 与证据链接
- `docs/case_brief.md`
- 简历 bullet、面试故事和下一阶段 backlog

## 完成标准

- 新读者能在页面上回答：先查什么、为什么、核查发现什么、下一步建议什么。
- 干净环境能够重建主要结果，或复现失败和原因已记录。
- 网站、memo 和下载数据的数字一致。
- 页面不会让人误以为是实时监控，也不会把建议状态显示成已经改善。
- 项目负责人可以不依赖页面朗读，解释一个指标、一段关键 SQL、一个 insight 和一次建议变化。

## 新对话开场提示

> 请阅读项目 Charter、`WORKSTREAMS.md`、`workstreams/06_OPEN_SOURCE_DELIVERY.md`、工作包 05 的最终材料和 `DECISION_LOG.md`。我们现在只执行工作包 06：把已有分析做成最小静态开源页面，验证从干净环境复现主要结果，并完成 README、case brief、简历 bullet 和面试故事。不要新增分析范围；页面中的数字和状态必须来自最终数据。
